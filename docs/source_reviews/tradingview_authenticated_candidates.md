# TradingView Authenticated Candidates Source Review

## Candidate Use

Authenticated TradingView mirror for three options/volatility series that have no approved free-public ingestion path: ICE MOVE (volatility of US Treasuries), Cboe put/call ratios, and the Cboe VX futures term-structure curve. The TradingView path lets the workflow refresh candidate-only context when the primary owners (Cboe, ICE) keep these series behind Cloudflare gating, paid DataShop licenses, or HTML-only pages with no machine-readable bulk endpoint.

This review covers all three target series as a single authenticated-candidate family because they share one source owner, one access mechanism, one secret pair, and one set of redistribution constraints. Each individual fetcher will land in a follow-up PR (C2 MOVE, C3 put/call, C4 VX curve) and append its filename to the secret-isolation allowlist at that time.

Listed as readiness-UI candidates only; no operational free-public path has been approved as of this review.

## Review Answers

Source owner: TradingView Inc. (https://www.tradingview.com).
Official page / documentation reviewed: https://www.tradingview.com (product home), https://www.tradingview.com/policies/ (Terms of Use and policies index), https://www.tradingview.com/support/solutions/articles/13000539706-real-time-data-on-tradingview/ (real-time/delayed data semantics). The Python client choice (community-maintained fork of the unmaintained `tvdatafeed` package) is pinned in PR C2 once validated against the live PyPI registry; this scaffolding PR (C1) does not import any TradingView client.
Data format: TradingView serves chart bars through an authenticated WebSocket-and-HTTPS session. The chosen community Python client (pinned in PR C2) wraps this session and returns a pandas DataFrame with a `DatetimeIndex` and `open`, `high`, `low`, `close`, `volume` columns. Symbols are addressed as `(symbol, exchange)` tuples; the specific identifiers for MOVE, put/call ratios, and the VX1-VX8 curve are confirmed in each follow-up PR's fetcher.
Historical availability: TradingView's authenticated session can return up to roughly 5000 daily bars per `get_hist` call for the supported symbols, which is well beyond the lookback any current dashboard panel needs. Coverage and bar quality depend on TradingView's licensing with the underlying owners (Cboe, ICE) and may change without notice.
Automated download allowed: Conditional. TradingView's Terms of Use forbid scraping the public website but allow authenticated client sessions for the account holder's own analytical use. The repo treats the TradingView path as an authenticated-candidate fallback, never as a free-public source. The fetch runs only inside GitHub Actions, gated on `ENABLE_AUTHENTICATED_CANDIDATES=true` plus both `TRADINGVIEW_USERNAME` and `TRADINGVIEW_PASSWORD` repo secrets being populated. The credential never appears in logs, in committed JSON, or in any error message — see exception scrubbing below.
Static JSON redistribution allowed: No. TradingView's Terms of Use do not authorize redistribution of underlying owner data (Cboe, ICE) as derived static datasets. Candidate JSON files written under `public/data/candidates/` therefore carry `public_redistribution_allowed: false` and `requires_secret: true`. The committed file ships the schema scaffolding plus the most recent observations the workflow could retrieve; a future review may flip `commit_observations` off and ship an empty `observations` array only.
Attribution requirement: TradingView and, where applicable, the underlying owner of the series (Cboe Global Markets for put/call and VX; ICE for MOVE). Citations in the dashboard footer or candidate panels must name TradingView as the authenticated mirror and note that the underlying series is owned by Cboe or ICE.
API key required: No traditional REST API key. The path uses a TradingView account username and password supplied as GitHub Actions repository secrets (`TRADINGVIEW_USERNAME`, `TRADINGVIEW_PASSWORD`). Activation is gated by a separate boolean repo secret `ENABLE_AUTHENTICATED_CANDIDATES`. None of these names appear in committed JSON, frontend code, or build artifacts. The secret-isolation test enforces this at every PR via an allowlist check.
Can it be used in browser: No. The browser must never call TradingView directly, must never see the username or password, and must never see a TradingView-derived URL that would carry a session token.
Can it be used in GitHub Actions ingestion: Yes, conditionally. The workflow step `Fetch, transform, score, and validate data` in `.github/workflows/update-data.yml` injects the three secrets into the environment. If any of the three is unset or empty, `tradingview_credentials_available()` returns `False` and every TV fetcher skips silently. The safe-update path in `scripts/update_data.py` preserves any prior good JSON when a fetcher skips or fails.
Can it affect active scores now: No
Recommended catalog status: terms_review_needed
Recommended score status: candidate
Citation text: TradingView authenticated candidate (https://www.tradingview.com). Mirrors MOVE, Cboe put/call, and Cboe VX1-VX8 curve through an authenticated session. Not a free-public source. Underlying series are owned by Cboe Global Markets and ICE. Candidate-only; never enters active scores, regime labels, page-insights primary slots, or checklists.
Notes / unresolved questions: The original `tvdatafeed` PyPI package is unmaintained (last release over three years ago, status "removed" on PyPI). PR C2 will pin the exact community-maintained fork name and version range in `requirements.txt` after verifying installability on PyPI; the master plan illustratively named `tvdatafeed-fork>=1.5,<2`, but that name does not currently resolve, so the C2 author re-validates against PyPI before committing. This scaffolding PR (C1) pins only the unconditional dependencies `pandas>=2.2,<3` and `requests>=2.32,<3` so CI's `pip install -r requirements.txt` step continues to succeed during the gap before any fetcher exists. The client (once pinned) must be configured to write any on-disk session cache under `tempfile.gettempdir()` via the `TVDATAFEED_CACHE_DIR` environment variable; each fetcher sets this before instantiating the client. Each fetcher wraps `get_hist(...)` in a try/except that scrubs `TRADINGVIEW_USERNAME` and `TRADINGVIEW_PASSWORD` values from any exception message before logging. The follow-up PRs C2/C3/C4 each add one fetcher plus its filename to the secret-isolation test's allowlist; this scaffolding PR ships zero fetchers, so the value-leak and cache-dir checks no-op until then. Re-review the source if TradingView changes its Terms of Use, if the chosen fork library becomes unmaintained, if a free-public Cboe or ICE endpoint appears, or if the project decides to license DataShop directly with appropriate budget and terms acceptance.

## Decision

Adopt TradingView as an authenticated-candidate fallback for MOVE, Cboe put/call, and Cboe VX1-VX8 curve. Catalog status `terms_review_needed`; score status `candidate`; `active_scoring_allowed: false`; `requires_secret: true`; `public_redistribution_allowed: false`. The scaffolding ships first (this PR) without any fetcher so the secret guard is observable and reviewable in isolation. Follow-up PRs C2, C3, and C4 each add one fetcher.

Re-review the source if TradingView changes its Terms of Use, if the `tvdatafeed-fork` library becomes unmaintained, if a free-public Cboe or ICE endpoint appears for any of the three series, or if the project decides to license DataShop directly with appropriate budget and terms acceptance.
